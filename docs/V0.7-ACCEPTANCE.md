# v0.7.0-rc.1 — native Windows / Arch acceptance

This is a **manual release gate**. All tests use a disposable loopback or
private test SSH/SFTP server with expendable files. **No corporate VPN, real
client server, production SSH connection or sensitive credentials are needed.**

## Preparation

1. On a native **Windows 10/11** machine with WebView2 and on a native
   **Arch Linux** desktop with Tauri 2 prerequisites, check out exactly the
   candidate SHA from PR #11. Do not assume that a WSL2/WebKitGTK preview
   verifies native Arch or Windows.
2. `npm ci`, `npm test`, `npm run build`; to start the actual desktop UI,
   run `npm run tauri dev`. Windows may also use the matching GitHub Actions
   `nodedesk-windows-preview` artifact; it is **not an installer**.
3. Use a disposable SFTP peer with a separately verified host key, one
   ordinary text file and several random binary test files (at least one
   larger than 8 MiB). Keep a known hash of each file for comparison.

## One pass on EACH OS

- [ ] Opens without crashes; RU/EN, tab/split, resizing, closing and
      connection catalog navigation behave correctly.
- [ ] SSH host-key trust is enforced; reject a deliberately changed host
      key, then restore the trusted test key (never bypass the warning).
- [ ] SFTP login via a supported key/agent or test password works.
      Files panes open **only when requested**; no auto-transfer.
- [ ] Create two file batches, switch their reports, and verify only one
      transfer runs at a time. Pause an active 8 MiB+ transfer; ensure the
      next queued file does not silently start.
- [ ] After pausing, reauthenticate if required (especially Windows native
      Files login), refresh both filesystem panels, explicitly resume from
      a partial. Compare final file bytes/SHA256 with the known test original.
- [ ] Retry a failed file without replaying an already-Done file.
      Attempt an existing destination name; NodeDesk refuses overwrite.
      Corrupt a disposable .part; verified resume fails before publication.
- [ ] Opt in to recovery, interrupt a multi-file batch, close NodeDesk and
      reopen it. Confirm NO automatic SSH connection/listing/transfer, then
      log in, load a saved queue, refresh both panes, and manually resume.
      Confirm Done files remain untouched.
- [ ] Opt out and **Forget saved queue**; confirm only metadata is removed,
      with no automatic .part deletion. Do not put secret filenames in this test.
- [ ] Open a disposable UTF-8 text file and use Find/Replace in memory.
      Save as a distinct copy; confirm source file unchanged.
- [ ] If a **disposable** Guacamole RDP / authenticated VNC WSS lab is
      available, confirm explicit connect, input, disconnect and no
      automatic reconnection. Otherwise mark this item **not verified**;
      do not call it a pass.

## Report

For each OS provide: OS/version, candidate SHA, which boxes passed/failed,
any error or screenshot with secrets redacted, and whether the test files'
SHA256 matched. A blank or unexecuted box is not a pass.

After both OS reports and exact-head CI are green, promote the candidate,
re-review third-party notices, merge approved PR, tag and publish v0.7.0.
