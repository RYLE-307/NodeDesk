# v0.7 release gate (working plan)

This milestone is a transfer-reliability release after the v0.6 desktop and
workspace review branch. It does **not** claim every row of
[MobaXterm parity](MOBAXTERM-PARITY.md). Serial, Mosh, X11, FTP/FTPS, Proxmox,
Zabbix, MikroTik, vault and advanced VPN remain later milestones unless a
separate reviewed scope change explicitly includes them.

## Required before `v0.7.0`

1. **Multiple SFTP queues:** independent, endpoint-bound plans and reports;
   bounded total work and explicit scheduling. A user can pause an active job,
   inspect other jobs, and explicitly retry or resume unfinished files. No
   overlapping writes to one destination; no automatic network activity after
   restart, tab opening or authentication. Completed files are never replayed.
2. **Recovery and interruptions:** opt-in checkpoint per queue, versioned and
   validated, with a clear retention and deletion policy. Restore requires
   authentication, fresh source and target listings, and user confirmation.
   Resume verifies the entire partial against its source before writing and
   rejects altered source metadata, collisions and invalid paths. Windows
   native login invalidation on cancellation must have an explicit reconnect
   path. Network disconnect, timeout and tab close leave accurate reports.
3. **Protocol evidence:** disposable real OpenSSH/SFTP and independent Windows
   SSH/SFTP peer tests include large binary files, mid-transfer interruption,
   byte-identical retry/resume, no-overwrite, changed/revoked host trust and
   credential privacy. Browser tests cover queue state and consent; they are
   UI contracts, not a substitute for native testing.
4. **Release hardening:** current Windows/Linux frontend, browser, Rust/Tauri,
   Guacamole and VNC workflows green on the exact candidate SHA. Dependency
   notices, version metadata, build/installation instructions and release
   notes must match the built source. No secrets, tokens or test credentials
   in catalog, checkpoint, release assets or logs.
5. **Manual acceptance:** a person must launch the candidate on native Windows
   and Arch and exercise the short SFTP/desktop/workspace checklist. CI on
   Ubuntu and Windows runners, Arch under WSL2 and browser automation do not
   establish this result. No corporate VPN or production connection is needed.

Until all gates pass, PR #11 stays draft and `main` remains unchanged. A
release tag, GitHub release and branch cleanup follow the verified merge.

## Status at the start of this milestone

The branch already has a single sequential 50-file batch, explicit retry,
byte-verified upload/download resume and one optional recovery checkpoint per
endpoint. It lacks the multi-queue manager, complete pause/reconnect UX,
larger cross-platform stress evidence and native acceptance. The existing
v0.6 desktop modules are reviewed as a bounded dependency, not automatically
expanded to full protocol parity.
