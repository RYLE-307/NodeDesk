# v0.8 engineering plan — functionality before appearance

This phase continues NodeDesk after the **v0.7.0-rc.1** automated milestone.
Per operator request, no incremental manual QA is required in v0.8: all native
Windows and Arch GUI acceptance is collected at **v0.9**, followed by
functional corrections and design polish through **v1.0**. CI coverage must
not be described as manual or production certification.

## Candidate deliverables

1. **Safe remote file maintenance:** POSIX chmod over SFTP v3 (regular files
   and directories only), explicit user consent, stale metadata refusal,
   no symlinks/special bits/sudo/local ACL changes. This is implemented in
   the development branch; native manual acceptance is deferred.
2. **SSH connection workflow:** improve SSH config/aliases and safe
   gateway selection without weakening known_hosts, password handling or
   executing arbitrary shell strings.
3. **Transfer reliability:** improve per-queue user visibility, cleanup
   guidance and interruption diagnostics without automatic replay; preserve
   exact-source verification before any byte-offset resume.
4. **Automated QA:** Windows/Linux Rust/Tauri builds, Playwright contracts,
   disposable SSH/SFTP binary/metadata integration and desktop WSS labs;
   regression checks for no automatic connection and zero saved credentials.

## Scope exclusions

No production VPN access; no customer hosts; no automatic reconnects, mass
port scans, unchecked remote chmod, silent overwrites, secret persistence,
background daemon or claimed native GUI acceptance. Visual redesign is
deferred until v1.0 stabilization.

## QA milestones

- v0.7: CI-only engineering release candidate.
- v0.8: continue functionality with automated tests and clearly marked
  experimental artifacts.
- v0.9: user performs one integrated native Windows/Arch acceptance campaign.
- v1.0: fix the defects found, improve design/accessibility, add any
  remaining agreed high-value functions, then prepare the actual release.
