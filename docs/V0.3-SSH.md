# NodeDesk v0.3 SSH vertical slice

This branch adds a real OpenSSH process attached to a native PTY (Unix PTY / Windows ConPTY), rendered by xterm.js through Tauri IPC channels. No external terminal, shell wrapper, simulated connection, remote service, or automatic connection is used. Open a catalog tab, then explicitly press Connect. Key authentication uses default OpenSSH identity files and/or the inherited local agent. Encrypted key passphrases are entered directly at the OpenSSH terminal prompt. Password and keyboard-interactive authentication are disabled.

## Trust and secrets

OpenSSH uses the OS user's standard known_hosts (including hashed entries and revocation markers), with StrictHostKeyChecking=ask, UpdateHostKeys=no and VerifyHostKeyDNS=no. An unknown host requires explicit confirmation of its SHA256 fingerprint in the terminal. Verify it through a trusted independent channel before answering yes. A changed or revoked key is rejected; NodeDesk never deletes trust entries or offers an insecure override. No ssh-keyscan result is trusted for production connections.

The adapter uses argv without a shell and validates destination/user/port/size. It ignores ssh_config with -F none, disables forwarding, local commands, multiplexing, password prompts and local escape commands. Therefore aliases, custom IdentityFile, ProxyJump and ProxyCommand are intentionally unavailable. OpenSSH must be installed and trusted on PATH. The agent is local only, never forwarded. No credential is written to catalog/localStorage, argv, logs or Git. Terminal output stays in memory (2000 lines); do not type secrets into commands that a remote shell will echo or store in history. There is no transcript recorder, telemetry or OS vault yet.

## Lifecycle and UI

Each open catalog SSH tab owns one terminal and at most one process. Hidden tabs stay mounted, retain output and keep their sessions. Split displays two different open tabs; selecting the same tab shows one terminal, not a second connection. Input is serialized, output is transported as bytes, PTY resize propagates to the server, and stdout/stderr are naturally merged by the PTY. Disconnect/cancel/close/delete/window destruction terminate the local SSH process. The reader thread reaps it. Late connection completion after cancellation is closed again. Reconnect is always explicit and creates a new session ID. Exit code and startup errors are visible. The UI says SSH started rather than claiming authentication succeeded; remote shell output is the evidence of successful authentication.

Limits: 16 simultaneous sessions, terminal 2–500 columns / 2–300 rows, 64 KiB per input message. No password auth, arbitrary key picker, SFTP, tunnels, session restoration, broadcast input, or separate stdout/stderr panes. OS OpenSSH prompts remain in its installed language; NodeDesk controls/help are RU/EN. Terminal uses a fixed dark palette inside the existing light/dark/system application. A slow frontend can accumulate queued IPC output: sustained bulk-output backpressure remains future work. Windows ConPTY and agent/passphrase behavior still require manual verification on a real installation.

## Arch manual acceptance (required before merge)

Use a fresh clone if the existing checkout has untracked Cargo.lock, xrdp/ or xorgxrdp/. Do not remove or overwrite those files.

```sh
sudo pacman -S --needed base-devel git nodejs npm rust webkit2gtk-4.1 libappindicator-gtk3 librsvg openssh
git clone --branch feat/v0.3-ssh https://github.com/RYLE-307/NodeDesk.git NodeDesk-v03
cd NodeDesk-v03
npm ci --registry=https://registry.npmjs.org
# If the default registry is unavailable:
# npm ci --registry=https://registry.npmmirror.com
npm test
cargo test --manifest-path src-tauri/Cargo.toml
npm run tauri dev
```

For an existing CLEAN checkout: git fetch origin, then git switch --track origin/feat/v0.3-ssh (or git switch feat/v0.3-ssh if already present), then git pull --ff-only. If package-lock registry URLs are inaccessible, a fresh-clone-only workaround is npm install --registry=https://registry.npmmirror.com --replace-registry-host=always; review the resulting lockfile and do not commit unrelated registry changes.

Use a disposable SSH server/account with a default identity key or load an encrypted key with ssh-add before launching NodeDesk from the same environment. Confirm ssh -V. Add two SSH catalog entries with username; opening them must generate no network traffic until Connect. Check unknown fingerprint rejection (answer no); retry and confirm the independently verified fingerprint; run tty, printf, an interactive editor and stty size. Resize, switch tabs, and split two connections; input/output must stay with the correct tab. Run exit and reconnect. Cancel while connecting; close a live tab; close the application; verify no child ssh process remains. Test invalid user, unreachable port and server shutdown. In an isolated test account/known_hosts, replace the server host key and verify connection refusal; do not alter production trust files to run this test. Test both themes and RU/EN. Never merge before completing this check on Arch.

Windows: install Rust MSVC + Visual Studio C++ Build Tools, Node >=22.12, WebView2 and the Windows OpenSSH Client optional feature; ensure ssh.exe is on PATH. Launch from an environment with the intended agent. Run npm ci and npm run tauri dev. No WSL is required.

## Automated checks

Frontend tests/build run on Linux and Windows. Desktop CI runs Rust tests and a Tauri no-bundle build on both OSes. Linux additionally starts an isolated loopback sshd with generated ephemeral keys: tests reject an unknown key, explicitly approve it, reuse known trust, reject a changed key and a revoked key. Rust tests validate argument injection, secure options, dimensions and killing/reaping a PTY child on session drop. Missing local Rust or desktop runtime does not count as a passed desktop test. Manual Arch/Windows interaction and authentication remain required.
