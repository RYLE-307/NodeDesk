# v0.7 release gate (release-candidate plan)

This milestone is a transfer-reliability release after the v0.6 desktop and
workspace review branch. It does **not** claim every row of
[MobaXterm parity](MOBAXTERM-PARITY.md). Serial, Mosh, X11, FTP/FTPS, Proxmox,
Zabbix, MikroTik, vault and advanced VPN remain later milestones unless a
separate reviewed scope change explicitly includes them.

## Required for the v0.7 automated engineering milestone

1. **Multiple SFTP queues:** independent, endpoint-bound plans and reports;
   bounded total work and explicit scheduling. A user can pause an active job,
   inspect other jobs, and explicitly retry or resume unfinished files. No
   overlapping writes to one destination; no automatic network activity after
   restart, tab opening or authentication. Completed files are never replayed.
2. **Recovery and interruptions:** opt-in checkpoint per queue, versioned and
   validated, with a clear retention and deletion policy. Restore requires
   authentication, fresh source and target listings, and user confirmation.
   Resume verifies the entire partial against its source before writing and
   rejects altered source metadata, collisions and invalid paths. Windows
   native login invalidation on cancellation must have an explicit reconnect
   path. Network disconnect, timeout and tab close leave accurate reports.
3. **Protocol evidence:** disposable real OpenSSH/SFTP and independent Windows
   SSH/SFTP peer tests include large binary files, mid-transfer interruption,
   byte-identical retry/resume, no-overwrite, changed/revoked host trust and
   credential privacy. Browser tests cover queue state and consent; they are
   UI contracts, not a substitute for native testing.
4. **Release hardening:** current Windows/Linux frontend, browser, Rust/Tauri,
   Guacamole and VNC workflows green on the exact candidate SHA. Dependency
   notices, version metadata, build/installation instructions and release
   notes must match the built source. No secrets, tokens or test credentials
   in catalog, checkpoint, release assets or logs.
5. **Explicit scope label:** v0.7 may be merged as an *engineering release
   candidate* with exact-head automated CI only. It is **not validated** on
   native Windows/Arch by the user, not production-ready and not a signed
   installer. Consolidated manual testing is deferred until v0.9–v1.0 by
   explicit operator decision. CI cannot be cited as proof of manual GUI QA.

Until automated gates 1–4 pass, PR #11 stays draft and `main` remains
unchanged. Once green, the candidate may be merged to keep branches small;
any v0.7 version/tag remains clearly **prerelease / CI-only** rather than a
production-stable release. Native release validation is a v0.9–v1.0 gate.

## Implementation status in draft PR #11

The branch now keeps up to eight independent queue reports in a Files tab,
with one active transfer at a time. An active queue can be paused by cancelling
its current operation. The partial is retained only under the existing safe
rules; explicit verified resume compares its bytes to the source. Retries and
resumes require freshly loaded local and remote panes. Optional recovery now
stores separate checkpoints for multiple queues, including on the same
endpoint, and refuses a ninth checkpoint rather than silently evicting
unfinished work. Paused work never starts itself after restart. Windows native
login may need to be re-established after cancellation.

Linux CI uses a disposable real sshd for an 8 MiB+ interruption/resume test;
Windows CI uses a separate Paramiko SSH/SFTP peer for a 4 MiB+ binary round
trip. These are automated evidence, not native GUI acceptance. The existing
v0.6 desktop modules are a bounded dependency, not an expansion to full
protocol parity.

The former v0.7 engineering checkpoint used **0.7.0-rc.1**. Current active
source metadata is **0.8.0-alpha.0** while more functionality is added. The
v0.7 milestone was **not published as a stable release or installer**. Check
[release notes](RELEASE-NOTES-V0.7.0.md),
[third-party notices](THIRD-PARTY-NOTICES.md), and
[manual acceptance checklist](V0.7-ACCEPTANCE.md).

Engineering gates: CI green on exact candidate HEAD and notes/notices/version
review. Manual native Windows/Arch acceptance moved to **v0.9–v1.0**.
Packaging and signed installation are deferred until that campaign. A background transfer service independent of an open tab is
outside this milestone: on tab close a transfer is cancelled and a checkpoint
can be manually restored after the next login.
