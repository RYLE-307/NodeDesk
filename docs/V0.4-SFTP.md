# NodeDesk v0.4 SFTP console MVP

This branch adds a **real interactive SFTP command-line client** inside the NodeDesk window, powered by the system's OpenSSH `sftp` executable on Linux or Windows. It is deliberately **not advertised as the finished graphical SFTP browser**.

Each SSH catalog tab now has SSH and SFTP subtabs. Neither starts automatically. Both can remain connected while switching subtabs, and close together with the catalog tab. The user explicitly clicks Connect in the SFTP subtab. Authentication modes Auto, Key and Password/PAM are identical to the existing SSH tab. Host fingerprint prompts must be checked independently; changed/revoked keys remain blocked. Separate native PTYs stream output into xterm.js. This is not a server-side shell wrapper.

After a successful SFTP login you see `sftp>`. Try `pwd`, `ls`, `cd /tmp`, `help`, `get remote.txt`, `put local.txt`, `bye`. **Run `lcd /trusted/local/folder` before get/put**: without it the current local path can depend on the environment in which NodeDesk was launched. Avoid running arbitrary `!` local-shell commands exposed by the OpenSSH SFTP client itself. The UI does not collect or persist file paths or credentials.

## Validation

Automated: Rust tests check SFTP argument construction, rejected destinations, correct -P port syntax, and OpenSSH host-trust options. Existing SSH host-key, lifecycle and frontend tests remain. CI compiles Tauri on Windows and Linux. This does not replace runtime validation of the SFTP binary, auth and transfers.

Manual acceptance on Arch and Windows:
1. Install system OpenSSH with `sftp`. Open an SSH catalog entry and switch to SFTP.
2. Verify no connection until explicit Connect. Check host fingerprint independently.
3. Test correct and incorrect password/PAM, and key/agent where configured.
4. At `sftp>`, run `pwd`, `ls`, `cd`, `lcd`. On a disposable test file, transfer `put` and `get`, then verify bytes at both ends.
5. Switch between SSH and SFTP; sessions must remain isolated and not leak input across tabs. Disconnect, reconnect and close the app; check no orphan `ssh`/`sftp` child process.
6. Check errors for unreachable server, missing `sftp`, bad credentials, and changed/revoked host key on an isolated test host.
7. Inspect output in RU/EN and light/dark/system. The terminal itself currently has a fixed dark palette.

Limitations: no GUI file browser, no filesystem drag/drop, no resumable/background transfer management, no dedicated transfer-directory setting, no progress integration, no transfer queue, and no Windows runtime evidence yet. NodeDesk itself does not save passwords; terminal text remains in runtime memory. No SFTP session resumes automatically.
