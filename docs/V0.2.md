# NodeDesk v0.2 alpha

## Implemented

- Connection CRUD (SSH/RDP metadata only), nested group CRUD and moving through forms.
- Group deletion removes descendants and moves their connections to the root.
- Search across name, host, user, protocol and full group path; favorites filter.
- RU/EN, dark/light/system (including live OS theme changes), opt-in monitoring panel.
- Collapsible navigation, empty startup workspace, closable top tabs and two detail panes.
- No active tabs restored at startup, no network sessions or automatic connections.

## Storage contract

WebView localStorage key `nodedesk.catalog.v1` contains schema version 1 and only
catalog metadata and preferences. This is local profile storage, not encrypted
storage or a portable backup. There are no password, private-key, token, command
or credential-URL fields. Do not put secrets into names or usernames.

Every read/write validates the schema, references, unique IDs, ports, bounded
strings, group cycles and document size. Unknown properties are discarded.
Unsupported future versions and corrupt data block writes; the original value
is not overwritten. There is no earlier persisted catalog schema to migrate.
Future versions must add an explicit migration before accepting older formats.

Writes happen before updating React state. A storage/quota error leaves the
current catalog and editor intact. Reload retries reading storage; it does not
clear it. To recover corruption, back up the raw value using WebView developer
tools, repair it, then reload. There is deliberately no automatic destructive
reset. Multiple app instances/windows editing the same profile are not supported
(last successful write wins). Clearing app/browser data removes the catalog.

## Manual acceptance checklist (Windows and Arch)

1. Run `npm ci`, `npm test`, `npm run build`, `npm run tauri dev`.
2. Verify empty workspace, no tabs, monitoring off and no network connections.
3. Add a group and child group; add SSH and RDP records, edit and move them.
4. Search by host/user/parent path, toggle favorites, collapse/expand groups.
5. Open records, switch/close tabs, split and choose a secondary record.
6. Delete an open record; delete a parent group and verify records survive at root.
7. Switch RU/EN and all themes, change OS theme with System selected.
8. Restart: catalog/settings return, tabs do not.
9. Set the storage value to invalid JSON: verify read-only error and original
   value preserved. Restore the backup and reload. Simulate blocked/quota storage:
   a failed save must keep the form and previous catalog.

Frontend unit tests cover persistence, validation, cycles, deletion and storage
failures. CI builds frontend and Tauri without bundling on Windows and Ubuntu.
Ubuntu CI does not replace Arch desktop acceptance. Real SSH/SFTP/RDP, protected
secret storage, monitoring providers, session lifecycle and installer signing
remain future work. Detail panes never simulate a terminal or live metrics.
