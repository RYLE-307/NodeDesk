# v0.9 — consolidated native Windows/Arch acceptance

**Prepared, not performed.** The operator requested one combined manual
testing campaign at v0.9–v1.0 after functional development. v1.0 will then
address defects, accessibility and final UI/UX design.

## Setup

Test the exact candidate commit on both a native Windows 10/11 system and
a native Arch Linux desktop. Record OS version, SHA, setup method and any
missing dependencies. Use disposable SSH/SFTP lab hosts and synthetic files
with known SHA256; no corporate VPN, production infrastructure or secrets.

## Native checklist, repeated once on each OS

- [ ] Catalog CRUD, groups, context menus, favorites, import/export,
      Quick Connect, RU/EN, themes, sidebar resizing, tabs and 1/2/4 panes.
- [ ] SSH: first host-key trust and changed-key refusal, password/PAM,
      key/agent, terminal input/resize/search and multiline paste warning.
- [ ] Read-only SSH config preview returns only allowed fields and never
      connects by itself. Explicit one-hop ProxyJump for SSH/SFTP console
      through a pretrusted disposable gateway; verify target AND gateway
      fingerprints. Test no unexpected config execution. GUI Files has no
      jump support.
- [ ] Graphical SFTP: local/remote browsing, permissions, guarded chmod,
      rename/delete/mkdir, text editor Save as new copy, no silent overwrites.
- [ ] Transfer manager: two queues, pause/cancel, retry, upload/download
      byte-verified resume after interrupting a file >=8 MiB, no replay of
      completed items. Inspect expected .part path; download redacted report
      and confirm no real host/path/filename/credential data.
- [ ] Explicitly opt in to two queue checkpoints; close/reopen; confirm
      no auto-login or transfer. Reauthenticate, refresh both panels,
      manually restore, and verify final SHA256. Forget queue metadata
      without deleting .part automatically.
- [ ] RDP and VNC via disposable gateways when available; confirm TLS,
      input, disconnect and absence of unintended reconnection. Mark
      unavailable integration as **not tested**, not passed.
- [ ] OS-managed VPN listing, without connecting corporate profiles.
      Confirm actions require manual confirmation and OS-level trust.
- [ ] DNS, TCP single/explicit port list, ping, traceroute, invalid inputs,
      changed-target stale-result suppression, no unsolicited scans.
- [ ] Performance and native GUI: startup/close, large-file memory,
      keyboard/focus/contrast, clipping, responsiveness and error recovery.

## Results

For each OS record passed/failed/not tested, exact SHA, minimal steps to
reproduce each bug and redacted screenshots/logs. Fix failures at v1.0 and
rerun exact-head CI plus affected real GUI scenarios before claiming
stable release. Only after that: final professional design polish,
remaining-priority features, installer validation, licenses and release.
